# 已发布页面【发布】改为直接同步更新

## 现状与结论
- 发布弹窗在编辑器顶栏 `apps/web/src/components/editor/topbar.tsx` 的 `PublishDialog`(L80-185),每次打开都要求填访问路径,且默认值按页面名重新生成(`slugify(pageName)`,L87),不是页面已发布的路径。
- 后端 `POST /api/pages/:id/publish`(`apps/server/src/routes/pages.ts:322`)已天然支持"再次发布=同步更新":覆盖 `publishedSchema`、slug 与自身相同放行、新旧 slug 缓存正确失效/重建。**后端和 `packages/schema` 均无需改动**。
- 核心缺口:编辑器 store(`apps/web/src/lib/editor-store.ts`)没存 `status`,前端无从判断页面是否已发布。

## 改动(仅前端 3 个文件)

### 1. `apps/web/src/lib/editor-store.ts`
- `LoadPayload`(L25)增加 `status?: "draft" | "published"`;`EditorState` 增加 `pageStatus`(初始 `"draft"`)与新 action `markPublished(slug: string)`。
- `load()`(L92)写入 `pageStatus: page.status ?? "draft"`。
- `markPublished: (slug) => set({ pageSlug: slug, pageStatus: "published" })`。

### 2. `apps/web/src/components/editor/editor-client.tsx`
- `load({...})`(L56)增加传入 `status: page.status`(`PageDetail` 已返回该字段)。

### 3. `apps/web/src/components/editor/topbar.tsx`
**Topbar:**
- 从 store 读 `pageStatus`、`pageSlug`;`canSyncPublish = pageStatus === "published" && !!pageSlug`。
- 新增 `handleSyncPublish()`:先 `saveNow()` 保存最新草稿 → `publishPage(pageId, pageSlug)` 直接同步 → 成功后 `toast.success("已同步更新线上内容", { action: { label: "查看", ... } })`;若失败且 `ApiError.status === 409`(路径被占用/保留字),toast 提示并自动打开发布弹窗让用户改路径;其他错误 toast 报错。
- 发布按钮改为分体式(用 `@lc/ui` 现成的 `DropdownMenu`):
  - 已发布页面:`[🚀 发布 | ▾]` — 点主体直接同步发布(期间禁用并显示"发布中…"),点 ▾ 下拉出"更改访问路径…",打开原弹窗(预填当前路径)。
  - 草稿页面:保持现状,单个按钮打开弹窗(弹窗内可填/改路径)。
- 新增导入:`DropdownMenu 系列`(来自 `@lc/ui`)、`ApiError`(来自 `@/lib/api`)、lucide 的 `ChevronDown`。

**PublishDialog:**
- 从 store 读 `pageSlug` 与 `markPublished`。
- 默认路径改为 `slug ?? pageSlug ?? slugify(pageName)`(L87)——弹窗预填页面已有路径,不再按页面名重新生成(下线后重新发布、更改路径两个场景都受益)。
- 发布成功后调用 `markPublished(res.slug)`:store 状态即时同步为已发布,同一会话内再点【发布】就走直接同步,无需刷新。

## 验证(dev 环境冒烟,只用自建测试页)
1. 新建草稿页 → 发布(弹窗填路径)→ 修改内容 → 再点【发布】:不弹窗直接同步,打开线上链接能看到新内容。
2. 已发布页面点 ▾ →"更改访问路径…"→ 改路径发布:新路径可访问、旧路径失效。
3. 草稿页与"下线后重新发布"的页面:点【发布】仍弹窗,且预填原路径。
4. 同步发布遇路径冲突(409):自动回退弹窗并提示。
