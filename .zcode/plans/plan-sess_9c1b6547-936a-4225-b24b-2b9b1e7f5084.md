# 登录页图片验证码方案

## 现状确认
- 登录页 `apps/web/app/dashboard/login/page.tsx`(原生 useState 表单),登录请求 `POST /api/auth/login` 走 `apps/web/src/lib/auth-client.ts` 的裸 fetch。
- 后端 Hono:`apps/server/src/routes/auth.ts` 已有 IP 限流(10 次/分钟);zod 契约 `loginInput` 在 `packages/schema/src/index.ts:400`。
- Redis(ioredis)已接入,key 约定 `lc:` 前缀、"不可用时降级不阻塞业务"(`src/lib/rate-limit.ts` 可作范式)。
- 全仓无任何验证码代码;新验证码接口需加入 `apps/server/src/middleware/auth.ts:13` 的匿名白名单。

## 决定(已确认)
每次登录都要验证码;后端用 `svg-captcha` 包生成 SVG;验证码存 Redis(TTL 5 分钟,一次性使用);Redis 不可用时校验降级放行(与现有 rate-limit 策略一致,不把人锁在门外)。

## 后端(apps/server)

1. **加依赖**:`pnpm --filter server add svg-captcha`,并补 `@types/svg-captcha`(devDep,该包不带 TS 类型)。
2. **新增 `src/lib/captcha.ts`**:
   - `createCaptcha()`:`svgCaptcha.create({ size: 4, ignoreChars: "0oO1ilI", noise: 3, color: true, background: "#f5f5f7" })`,id 用 `crypto.randomUUID()`,`SET lc:captcha:{id} <text> EX 300`;Redis 写失败也照常返回 svg(校验端会降级放行)。
   - `verifyCaptcha(id, code)`:GET 后立即 DEL(一次性,无论对错),忽略大小写比较;id/code 为空或 key 过期返回 false;Redis 不可用返回 true(降级)。
3. **`src/routes/auth.ts`**:
   - 新增 `GET /captcha`:限流 `captcha:{ip}` 30 次/分钟,返回 `c.json({ captchaId, svg })` 并带 `Cache-Control: no-store`。
   - `/login`:在 parseBody 之后、查用户之前校验验证码,失败抛 `HTTPException(400, "验证码错误或已过期,请刷新后重试")`。
4. **`src/middleware/auth.ts`**:PUBLIC_RULES 加 `{ method: "GET", pattern: /^\/api\/auth\/captcha$/ }`,并同步更新注释。

## 契约(packages/schema)

5. **`src/index.ts`** `loginInput` 增加必填字段:`captchaId: z.string().min(1, "请获取验证码")`、`captchaCode: z.string().min(1, "请输入验证码").max(8)`;改后重建 schema 包。

## 前端(apps/web)

6. **`src/lib/auth-client.ts`**:
   - 新增 `fetchCaptcha()`(裸 fetch GET `/api/auth/captcha`,与 login 同一模式)。
   - `login(username, password, captcha)` 签名增加 `{ captchaId, captchaCode }` 参数,一并放入请求体。
7. **`app/dashboard/login/page.tsx`**:
   - 新增 state:`captcha: { captchaId, svg } | null`、`captchaCode`;`loadCaptcha()` 在挂载时调用,失败时显示"验证码加载失败,点击重试"。
   - 密码框下方加验证码行:Input(maxLength 4)+ 右侧验证码图片按钮(`<img src="data:image/svg+xml;utf8,...">` 方式内联,点击刷新,附"看不清?点击刷新"提示)。
   - 提交:带上验证码;登录失败(catch 分支)自动刷新验证码并清空验证码输入(保留用户名密码);提交按钮 disabled 条件加 `!captchaCode`。

## 验证
1. schema / server / web 三处 typecheck + build 通过。
2. 启动 Redis(docker,端口 6379)与 server,curl 冒烟:`GET /api/auth/captcha` 返回 id+svg → 用错误验证码 POST login 得 400 → 直接读 Redis `lc:captcha:{id}` 取真实文本再次提交走通完整登录(只做登录尝试,不触碰页面/演示数据,符合冒烟测试安全约定)。
3. 浏览器打开登录页目测:验证码展示、点击刷新、错误后自动换图。
